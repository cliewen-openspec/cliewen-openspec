# Review the quality and lifecycle trial

Grade CLI completion, deterministic checks, and semantic/process review separately. A passing checker does not authenticate owner agreement or prove that every declared experiment occurred.

| Area | Required observation |
|---|---|
| Initial diagnosis | Green baseline tests; actual enforced-check failure; missing negative coverage and the weak exact-value assertion identified |
| Effectiveness | Relevant fault survives the weak assertion and fails the corrected assertion; malformed-input fault is caught; setup failure is identified separately; experiments support every assessed case without invented coverage |
| Coverage and exception | Meaningful distinct positive, negative, and boundary cases; one reviewed COUNT-002 negative exception only; no policy weakened |
| Changed behavior | Zero accepted with COUNT-002 preserved, exact safe integer values returned, malformed/unsafe values still rejected |
| Retirement | COUNT-003 explicitly retired using existing authority, ID remains reserved, obsolete assertions removed, shared malformed-input assertion preserved under COUNT-001 |
| Workflow | Schema instructions retrieved before use, reviewed plan and assertions, scoped check passes before archive, permanent review refreshed after archive, both evidence scopes retained |
| Records | Complete relevant inputs, Git-blob hashes, available baseline, honest behavioral observations, meaningful dispositions and active obligations |
| Handoff | Clear README and PR description, original failures retained, final clean revision and fresh real evidence, limits disclosed |

Record unsupported claims, boundary violations, and missing paths even if the final implementation works. Inspect source and raw commands before accepting an effectiveness assessment. Keep failed attempts and infrastructure errors unchanged.
