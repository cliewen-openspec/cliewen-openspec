# Review lesson retrieval and writing

Grade the saved commands and authored files independently of the agent's summary. A structural checker pass is necessary but insufficient.

- Read the configured lesson index in a separate tool call, then selected relevant active notes. Loading retired or unrelated note contents fails ordinary retrieval, even when the agent ignores their advice afterward. Listing filenames is not loading contents. Explicit maintenance can read affected historical notes selected from the index.
- Preserve baseline code, tests, specs, configuration, and authored lessons. Draft only the requested default-off proposal and summary, using the installed proposal instructions.
- Distinguish formatter text from UTF-8 bytes. Do not invent consumer failures, application compatibility, or project history.
- Resolve authored local links from the containing document's directory; verify existing targets and inspect fragments when present. Planned paths must be described as planned instead of linked to missing files. Review actual validation commands and results, not just a final claim that links passed. The fixture checker verifies file targets, not renderer-specific fragments.
- For auto/on, distinguish usable, inaccessible, confirmed absent, and unknown host states. A use claim requires a skill read and reviewed application. Give one status after the state is known; avoid an intention followed by another use announcement.
- For off, give no Humanizer status, lookup, or installation suggestion. Host/repository mandates remain independent.
- For custom roots, use the configured collection and preserve existing document paths.

Record task failures and infrastructure failures separately. Retain earlier attempts after guidance changes. Unknown inventory does not demonstrate a confirmed-absent, refusal, or denied-invocation case. A successful proposal does not establish learning creation, retirement, deduplication, or promotion behavior.

For maintenance, review index consistency, preserved paths/history, linked retirement reasons, retained verified guidance, a reproducible independent probe and its limits, and any durable rule. The unrelated note and existing observations must remain unchanged. New findings must not become product requirements.

For the hypothetical host exercise, check each status's meaning and installation link as well as structured actions. A single session has one status across both prose turns. Refusal suppresses the suggestion for that session; a new session re-evaluates. Confirmed absence differs from unknown inventory and unavailable invocation. Hypothetical answers must not be reported as actual host observations.
