# 0.6.0 release candidate

## Agent trials

Three fresh Windows CLI sessions used disposable projects initialized with the packed candidate. Each project contained two revisions of a synthetic exporter and an existing design under `docs/architecture`. The request called for a reusable transition analysis and a review of one commit. Two clients had to migrate independently while existing callers retained the CSV default. The preview commit changed the default to JSON. Client source and deployments were unavailable.

| Host | Observed result |
|---|---|
| Claude Code 2.1.332 | Recorded alternatives in `docs/analysis`, linked the existing design, and identified the changed default through a direct diff review and execution probes. Its host review skill would have required spawning agents, which the trial disallowed. |
| Codex CLI 0.170.0 | Produced a reusable analysis, identified the default regression, and kept its decision proposed. It also created a new design directory alongside the existing architecture directory and additional planning artifacts. |
| OpenCode 2.2.5 | Recorded migration options in `docs/analysis`, linked the existing design, and identified the default regression using the diff and local execution. |

The maintainer session inspected the trial outputs and Git status independently of the three reviewers. All three preserved the exporter and identified the missing client evidence. These trials exercised direct review. Successful delegation to a native review command remains unobserved. The additional Codex artifacts show that document placement and proportionality still require judgment.

## Upgrade check

The first candidate rejected the current 0.5.0 manifest. The final package adds 0.5.0 to the supported installation list. Only the compiled release metadata and the bundled configuration reference changed between the two tarballs. Agent-facing instructions were identical.

On a clean clone with the repository's 0.5.0 installation, update replaced the three schemas, planning and closure references, and manifest. The second preview listed no writes or deletes. The working tree showed no changes to project configuration or authored files. The final candidate tarball has SHA-256 `27548dac857079c596cba4ef98102ccfdca69cc1a2a4f0d101f71e8463e51a53`.

The full Windows suite passed all 196 existing tests. Five additional scoped installation checks passed for the new scenarios. The guide build checked 13 pages, 561 local links, and five diagrams.
