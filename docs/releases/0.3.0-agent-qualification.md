# Qualify 0.3.0 with all three coding agents

Every shipped feature in 0.3.0 needs independently reviewed evidence from Codex CLI, Claude Code, and OpenCode before publication. The original candidate came from `20b6939` with SHA-256 `7e5025af5e5b9e0beb04c79f3dbbeacbe2d79ebc3fc83704d6f2f03dbbe2486f`. The revised candidate has SHA-256 `0d5736e80a0ba055a8adf23638f0f6082d8ad8a3a9d9d248e4a6f1e4e0154459`. Unpacking both tarballs found changes in the Humanizer instructions and the installer code that attaches those instructions to the separate archive reference. The ledger binds each trial to its candidate.

A pass records the exact CLI, model, environment, fixture, commands, and independently reviewed outcome. A group closes when every listed behavior has evidence for all three agents. Mechanical behavior uses repeatable package checks and direct CLI observations. Workflow guidance also needs evidence that the agent followed it on the relevant path. Timeouts, setup errors, incomplete handoffs, and unrun paths stay open.

### Configuration coverage

The [configuration reference](../configuration.md) lists the choices a project can make. On November 21, `npm test` passed all 180 tests against the revised candidate on Windows with Node 24.0.0. A fresh pack matched the recorded candidate SHA-256. The suite exercises defaults, overrides, invalid settings, and selected interactions. For example, it changes planning and documentation settings independently across the native schemas and checks that authored files and workflow graphs are preserved. The agent matrix records real workflow execution separately.

On November 20, a focused Windows and Node 24.0.0 run checked 81 configurations against the built 0.3.0 code:

- All 27 combinations of `off`, `advisory`, and `enforce` for links, frontmatter, and Mermaid. A fixture supplied one issue per category. The report suppressed disabled categories, warned in advisory mode, and blocked when an enforced category found an issue.
- All 54 combinations of `off`, `review`, and `enforce` for coverage, effectiveness, and lifecycle, with evidence enabled or disabled. The 35 supported combinations reported the expected policy severities and blocking behavior. The 19 combinations that enforced at least one policy with evidence disabled were rejected as invalid. The fixture supplied execution-report data to isolate policy behavior.

A separate adapter run collected real test results with a custom test type and a nested, ignored evidence path containing a space. `check` read the custom report and tied it to the recorded Git revision. The adapter refused the unignored path and refused to overwrite an existing tracked report.

These results cover the named settings and fixture outcomes. The end-of-change fixtures passed independent checks and all eight fault probes across the three agents, including focused recoveries in OpenCode and Claude. The live ticket read, planning-disabled, transport failure, rejected credentials, and permission-restricted ticket cases passed across all three. The CI and skill fixtures with simulated host responses remain scoped to those responses.
