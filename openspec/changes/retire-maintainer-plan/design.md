## Approach

Use the existing OpenSpec changes and specs directories as the entry points for current work and accepted behavior. Put durable workflow, release, and outreach agreements in `AGENTS.md`. Keep completed work in the OpenSpec archive and release records.

Point historical links to the version of the roadmap that describes their work. Keep the final version available in [Git history](https://github.com/cliewen-openspec/cliewen-openspec/blob/fb3315e0dbb21e969e02ae4da82225f5d9045bcd/plan.md). Only open a new proposal for a deferred idea when it is selected.

## Verification

Scan the tracked Markdown for live links to the removed file, verify the replacement targets, and run strict OpenSpec validation and the documentation build.
