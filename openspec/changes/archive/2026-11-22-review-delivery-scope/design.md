## Before implementation

Put the shared review in the installed work-scoping guidance. Reference it from Delivery apply instructions and the delivery branch of Combined. Run it after all planning artifacts are ready and before the first implementation task. In Combined, keep the existing agreement on the decision. Keep investigations and no-delivery outcomes on their existing review paths.

Start from the user's request or selected ticket and any authorized amendments. Follow each outcome and constraint to the relevant plan and verification, then look back from the tasks and design for unrequested work. If the request is unavailable, state what could be checked and what needs clarification. Reuse the same review after a material plan change.

## Before archive

Extend the existing closure guidance to inspect the delivery diff, tests, and affected documents. Use the reviewed scope and retained amendments as the comparison. Trace the requested behavior to the result and its evidence. Report separately when behavior is missing or verification is incomplete, respecting the project's enabled policies.

Keep each actionable warning short. Name the request or scope boundary, the specific gap or addition, and its impact. Fix clear in-scope omissions with appropriate verification. Record any accepted addition, removal, or deferral in an existing change artifact. Track deferred work in the selected planning authority when enabled. Keep unresolved material items visible for the archive decision and preserve existing archive authorization.

Reviews are agent guidance. They use the existing OpenSpec apply and archive entry points. Keep clean reviews brief and use existing artifacts or the handoff to record their outcome.
