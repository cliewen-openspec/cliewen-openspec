# Trace product goals to permanent specs

## Question and motivation

After a change is archived, can a maintainer tell which permanent specs support a user outcome that spans more than one capability?

## Scope and constraints

Pick one real archived change with a documented goal or user journey. Trace it using the project's existing documents and OpenSpec specs. Keep the goal and behavioral requirements in their current authoritative locations.

## Decision criteria and investigation limits

Record what can be traced, where the trail ends, and what a reader would need to continue. If the trail breaks, try descriptive links in the existing goal or journey. Use the result to decide whether any further workflow change is warranted.

## Existing knowledge

The [product context specification](../../../specs/product-context/spec.md) already directs agents to reuse relevant intent and link journeys to specs.
